# Build brief: "AI or IRL" workplace quiz

You are executing this task in a **fresh session with no prior context** — everything you need is in this document and `CLAUDE.md` in this same directory. Read `CLAUDE.md` first for the standing guidelines, then come back here for the task itself.

## What this is

A live quiz for a workplace event. 3-4 teams of ~6 people compete to guess, for each item shown, whether it is **AI-generated or real**. Purely for entertainment, but also meant to genuinely surprise people about the current state of AI.

## Settled design — do not re-litigate these, just build them

**Format**
- Pure entertainment — no debrief or explanation after each question, just score and move on.
- 30-40 minute slot, ~10-12 questions total, mixed order across the four modalities below (not blocked by type).
- Target difficulty: the best team should land around **60-70% correct**, not higher and not much lower. See "Difficulty calibration" below — this is the hardest part to get right.
- No prize — bragging rights only, so no tie-breaker mechanism is needed.

**Content — four modalities, roughly balanced across ~10-12 questions**
- Images (AI-generated vs. real photo)
- Short video clips (AI-generated vs. real footage), ~3-8 seconds each
- Audio: a short passage read aloud — AI text-to-speech vs. a real human voice (NOT voice cloning of a specific person — just "is this voice synthetic or human")
- Text: a short passage — AI-written vs. human-written

Every asset must be embeddable directly into a single self-contained HTML page (see "Technical constraints"), which means **every asset must be public-domain, Creative-Commons, or self-generated by you** — no copyrighted viral clips, no scraping real people's social media videos, no copyrighted news/movie footage.

All quiz-facing content — UI chrome, host instructions, and the audio/text passages themselves — must be in **Swedish**.

**Difficulty calibration (important)**
Don't just pick "obviously AI" vs "obviously real" pairs — that caps out well above 70% and defeats the point. For each modality, deliberately include both directions:
- Content that looks impressive/uncanny but is genuinely **real** (unusual real photos, real archival footage, a real human voice with unusual cadence, surprisingly polished real human writing).
- Content that looks mundane/plausible but is actually **AI-generated** (a boring, everyday-looking AI photo or clip, competent-but-generic AI writing).

If you only source "impressive = AI, boring = real" pairs, sharp teams will just pattern-match and blow past the target accuracy.

**Delivery**
- One self-contained web app, published as a Claude Artifact — not Kahoot, not Mentimeter, not PowerPoint.
- Two views in the same app:
  - **Host/shared-screen view**: shown on a projector to the whole room. Displays the current question's media, a "reveal answer" control, a "next question" control, and a live leaderboard.
  - **Team view**: each team opens this on one shared device (e.g. a team captain's phone) via a join link/QR code, picks a team name, and submits one AI/Real answer per question.
- State (team votes, current question, leaderboard) must be **live and shared across all connected devices** — this requires an Artifact runtime capability, not just static HTML. See Phase B below.
- The host manually reveals the answer and advances to the next question — no countdown timer, no auto-advance.
- After each reveal: show the correct answer and the updated live leaderboard. No explanation of "what gave it away" (keep it fast, pure entertainment).
- One submission per team, not per person.

## Technical constraints

- The published Artifact page has a **16MB total size cap**, including all embedded data (images/video/audio as data URIs or uploaded assets). Keep video and audio clips short (~3-8s) and compressed — this is non-negotiable, plan for it from the start rather than trimming after the fact.
- A strict Content-Security-Policy blocks embedding from arbitrary external hosts (no YouTube iframes, no hotlinked images/video from random sites). Media must be embedded directly (data URI or the Artifact asset-upload capability) or come from an explicitly allowed source.
